# 📋 PRD: Notion 포트폴리오 통합·최신화

## 1. 개요

| 항목        | 내용                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 프로젝트명  | Notion 포트폴리오 통합·최신화                                                                   |
| 목적        | Notion 포트폴리오 페이지와 그 하위 문서(이력서·지원서)를 분석해 하나의 최신 이력서로 통합한다   |
| 데이터 소스 | Notion 포트폴리오 페이지(`NOTION_PORTFOLIO_PAGE_ID`)와 그 하위 페이지. 별도 데이터베이스는 없다 |
| 처리 방식   | Claude API로 자동 병합·요약                                                                     |
| 출력        | 웹에서 미리보기·수정 후 Notion에 반영                                                           |
| 배포        | Vercel                                                                                          |

### 1.1 배경

- 지원 회사나 시기마다 이력서·지원서를 따로 만들다 보니 내용이 여러 문서로 흩어져 있고, 항목마다 표현이 다르거나 일부가 누락되어 있다.
- 지원서·포트폴리오에는 이력서에 없는 성과와 경험이 들어 있지만 이력서에는 반영되지 않았다.
- 이를 수동으로 합치고 갱신하는 일은 반복적이고 누락이 잦다.

### 1.2 목표

- 포트폴리오 하위 문서들의 경력을 중복 없이 하나의 타임라인으로 통합한다.
- 지원서·포트폴리오 본문에서 성과·경험을 추출해 해당 경력 항목에 보강한다.
- AI가 만든 결과를 사용자가 반드시 검토·수정한 뒤에만 Notion에 저장한다.

### 1.3 비목표 (MVP 제외)

- 회원 가입·다중 사용자 지원 (개인용 도구)
- 이력서 PDF·DOCX 내보내기
- 채용 공고 기반 맞춤 이력서 생성
- 이력서 버전 간 롤백 UI (Notion 페이지 기록 기능 활용)
- Notion 데이터베이스 기반 조회, 카테고리·기간 필터 (소스가 DB가 아님)

---

## 2. 사용자 시나리오

1. 사용자가 앱에 접속하면 포트폴리오 페이지의 하위 문서 목록이 표시된다.
2. 분석·병합할 문서를 여러 개 선택한다. (기본값: 전체)
3. "최신화 생성"을 누르면 Claude가 통합 이력서 초안을 만든다.
4. 미리보기 화면에서 변경점(diff)과 항목별 출처(어느 문서에서 왔는지)를 확인한다.
5. 항목을 직접 수정하거나 AI 제안을 수락·거절한다.
6. 확정하면 Notion에 새 이력서 페이지로 저장한다.

## 3. 주요 기능

### 3.1 Notion 문서 조회

- 포트폴리오 페이지의 하위 페이지 목록과 각 페이지의 본문 블록을 읽어 구조화된 텍스트로 변환한다.
- 문서별 제목·생성일·수정일을 목록에 표시한다.
- 포트폴리오 페이지 자체의 본문(하위 페이지 제외)도 하나의 문서로 취급한다.
- 지원 블록: 제목, 문단, 불릿·번호 목록, 표, 인용, 구분선, 토글. 이미지는 텍스트가 없으므로 건너뛰되 로그를 남긴다.

### 3.2 경력 병합

- 여러 문서의 경력, 프로젝트, 기술 스택, 학력, 자격 항목을 하나로 합친다.
- 같은 회사·프로젝트는 기간과 이름으로 식별해 중복을 제거한다.
- 항목이 서로 충돌하면(기간, 직함 등이 다른 경우) 임의로 고르지 않고 사용자에게 선택지를 보여준다.
- 최종 경력은 최신순으로 정렬한다.

### 3.3 문서 기반 보강

- 지원서·포트폴리오 본문에서 정량 성과, 역할, 사용 기술, 문제 해결 사례를 추출해 해당 경력에 연결한다.
- 근거가 없는 내용은 만들지 않는다. 모든 보강 항목에 출처 문서를 표시한다.

### 3.4 미리보기·편집

- 병합 결과를 이력서 형태로 렌더링하고, 기존 대비 변경점을 diff로 보여준다.
- 항목 단위로 수락·거절·직접 수정할 수 있다.

### 3.5 Notion 반영

- 확정된 이력서를 포트폴리오 페이지 아래 새 하위 페이지로 생성한다. (저장 위치는 가정안, 확인 필요)
- 기존 문서는 덮어쓰지 않는다. (비파괴 원칙)

## 5. Notion 데이터 구조

> 실제 워크스페이스를 API로 조회해 확인한 구조입니다. (2026-11-15)

### 5.1 포트폴리오 페이지

- 최상위 페이지 1개와 그 하위 페이지 4개(이력서·지원서 문서)로 구성된다. 데이터베이스는 없다.
- 모든 페이지의 속성은 `title`뿐이다. 날짜는 페이지 메타데이터(`created_time`, `last_edited_time`)를 사용한다.
- 본문은 페이지 content 블록이다. (제목, 문단, 불릿·번호 목록, 표, 인용, 이미지, 구분선)

### 5.2 환경 변수

```bash
NOTION_API_KEY=secret_xxx          # Notion Integration 토큰
NOTION_PORTFOLIO_PAGE_ID=xxxxxxxx  # 포트폴리오 페이지 ID
ANTHROPIC_API_KEY=sk-ant-xxx       # Claude API 키
```

- 모든 키는 서버 전용이며 `NEXT_PUBLIC_` 접두사를 쓰지 않는다.
- 포트폴리오 페이지를 Notion Integration에 연결(Connections)해야 하위 페이지도 읽을 수 있다.
- `src/lib/env.ts`의 zod 스키마로 위 변수를 검증한다.

## 6. 화면 및 API

### 6.1 화면

| 화면          | 경로            | 설명                                   |
| ------------- | --------------- | -------------------------------------- |
| 문서 선택     | `/resume`       | 하위 문서 목록에서 병합 대상 선택      |
| 병합 미리보기 | `/resume/merge` | 생성 결과, diff, 출처 표시, 편집, 저장 |

### 6.2 API

| 엔드포인트            | 메서드 | 설명                               |
| --------------------- | ------ | ---------------------------------- |
| `/api/resume/sources` | GET    | 포트폴리오 하위 문서 목록 조회     |
| `/api/resume/merge`   | POST   | 선택한 문서로 병합 초안 생성       |
| `/api/resume/save`    | POST   | 확정본을 Notion에 새 페이지로 저장 |

## 7. 아키텍처 및 데이터 흐름

```
Notion 포트폴리오 ─▶ 서버(하위 문서 조회·텍스트 변환) ─▶ Claude API(병합·보강, JSON 출력)
                                                          │
                                                   Zod 검증 ▼
                                   웹 미리보기(diff·편집) ─▶ 서버 ─▶ Notion 새 페이지
```

- Notion과 Claude 호출은 모두 서버에서만 수행한다.
- Claude 응답은 JSON 스키마(경력, 프로젝트, 기술, 학력, 출처 포함)로 받고 Zod로 검증한다.
- 입력이 길 경우 문서별로 먼저 요약한 뒤 통합하는 단계적 처리를 고려한다.
- Notion API 속도 제한(평균 3 req/s)에 대비해 요청을 직렬화·캐싱한다. 중첩 블록 재귀 조회로 호출 수가 많아질 수 있다.

### 7.1 권장 디렉토리

```
src/
├─ app/
│  ├─ resume/page.tsx
│  ├─ resume/merge/page.tsx
│  └─ api/resume/{sources,merge,save}/route.ts
├─ components/resume/     # 선택 목록, 미리보기, diff 컴포넌트
├─ lib/
│  ├─ notion.ts           # Notion 클라이언트·조회·저장
│  ├─ claude.ts           # Claude 호출·프롬프트
│  └─ env.ts              # 환경변수 검증 (기존 파일 확장)
└─ types/resume.ts        # 이력서 스키마(Zod)
```

6. **다듬기**: 에러·로딩 처리, 속도 제한 대응, Vercel 배포

## 10. 비기능 요구사항

- **정확성**: 모든 AI 생성 항목에 출처를 표시하고, 근거 없는 내용은 만들지 않는다. 저장 전 사용자 검토는 필수다.
- **개인정보**: 이력서·지원서에는 개인정보가 포함되므로 외부 공개 라우트를 두지 않고 접근을 개인용으로 제한한다. (예: 배포 시 비밀번호 보호 또는 인증 도입 검토)
- **보안**: API 키는 서버 전용이며 저장소에 커밋하지 않는다. `.env.local`에만 저장한다.
- **안정성**: Notion·Claude 호출 실패 시 재시도와 명확한 오류 메시지를 제공한다.
- **비파괴**: 기존 Notion 문서는 수정하지 않는다.
