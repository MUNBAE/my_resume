# 📋 PRD: Notion 포트폴리오 통합·최신화

## 1. 개요

| 항목        | 내용                                                                                               |
| ----------- | -------------------------------------------------------------------------------------------------- |
| 프로젝트명  | Notion 포트폴리오 통합·최신화                                                                      |
| 목적        | Notion 포트폴리오 페이지와 그 하위 문서(이력서·지원서)를 분석해 하나의 최신 이력서로 통합한다      |
| 데이터 소스 | Notion 포트폴리오 페이지(`NOTION_PORTFOLIO_PAGE_ID`)와 그 하위 페이지. 별도 데이터베이스는 없다    |
| 처리 방식   | 수동 연계: 앱이 프롬프트를 생성하고, 사용자가 ChatGPT 등에서 실행한 JSON 결과를 붙여 넣어 검증한다 |
| 출력        | 웹에서 미리보기·수정 후 Notion에 반영                                                              |
| 배포        | Vercel                                                                                             |

### 1.1 배경

- 지원 회사나 시기마다 이력서·지원서를 따로 만들다 보니 내용이 여러 문서로 흩어져 있고, 항목마다 표현이 다르거나 일부가 누락되어 있다.
- 지원서·포트폴리오에는 이력서에 없는 성과와 경험이 들어 있지만 이력서에는 반영되지 않았다.
- 이를 수동으로 합치고 갱신하는 일은 반복적이고 누락이 잦다.

### 1.2 목표

- 포트폴리오 하위 문서들의 경력을 중복 없이 하나의 타임라인으로 통합한다.
- 지원서·포트폴리오 본문에서 성과·경험을 추출해 해당 경력 항목에 보강한다.
- AI가 만든 결과를 사용자가 반드시 검토·수정한 뒤에만 Notion에 저장한다.

### 1.3 비목표 (MVP 제외)

- 회원 가입·다중 사용자 지원 (개인용 도구)
- 이력서 PDF·DOCX 내보내기
- 채용 공고 기반 맞춤 이력서 생성
- 이력서 버전 간 롤백 UI (Notion 페이지 기록 기능 활용)
- Notion 데이터베이스 기반 조회, 카테고리·기간 필터 (소스가 DB가 아님)

## 2. 사용자 시나리오

1. 사용자가 앱에 접속하면 포트폴리오 페이지의 하위 문서 목록이 표시된다.
2. 분석·병합할 문서를 여러 개 선택한다. (기본값: 전체)
3. "프롬프트 생성"을 누르면 선택한 문서 본문과 출력 형식 지시가 담긴 프롬프트가 만들어지고, 복사한다.
4. 사용자가 프롬프트를 ChatGPT(Pro) 등에 붙여 넣어 실행하고, 나온 JSON 결과를 앱에 붙여 넣는다.
5. 앱이 JSON을 검증(스키마·출처)하고 통합 이력서 초안을 보여준다. 검증에 실패하면 오류 내용과 수정 요청용 프롬프트를 안내한다.
6. 미리보기 화면에서 변경점(diff)과 항목별 출처(어느 문서에서 왔는지)를 확인한다.
7. 항목을 직접 수정하거나 AI 제안을 수락·거절한다.
8. 확정하면 Notion에 새 이력서 페이지로 저장한다.

## 3. 주요 기능

### 3.1 Notion 문서 조회

- 포트폴리오 페이지의 하위 페이지 목록과 각 페이지의 본문 블록을 읽어 구조화된 텍스트로 변환한다.
- 문서별 제목·생성일·수정일을 목록에 표시한다.
- 포트폴리오 페이지 자체의 본문(하위 페이지 제외)도 하나의 문서로 취급한다.
- 본문은 마크다운 텍스트로 변환한다: 제목, 문단, 불릿·번호 목록, 표, 인용, 구분선, 토글. 이미지·임베드는 텍스트가 없으므로 제거하고 개수를 로그로 남긴다.

### 3.2 경력 병합 (수동 연계)

- 앱은 병합을 직접 수행하지 않고, AI가 병합하도록 지시하는 프롬프트를 생성한다. 프롬프트에는 문서별 ID·제목·본문과 출력 JSON 스키마, "근거 없는 내용 금지" 규칙이 포함된다.
- 사용자가 붙여 넣은 결과는 앱이 JSON으로 추출·Zod 검증하고, 출처 ID가 실제 문서에 존재하는지 확인한다.
- 프롬프트가 지시하는 병합 규칙은 다음과 같다. 앱은 결과를 검증·정규화(정렬·중복 보정)한다.
- 여러 문서의 경력, 프로젝트, 기술 스택, 학력, 자격 항목을 하나로 합친다.
- 같은 회사·프로젝트는 기간과 이름으로 식별해 중복을 제거한다.
- 항목이 서로 충돌하면(기간, 직함 등이 다른 경우) 임의로 고르지 않고 사용자에게 선택지를 보여준다.
- 최종 경력은 최신순으로 정렬한다.

### 3.3 문서 기반 보강

- 지원서·포트폴리오 본문에서 정량 성과, 역할, 사용 기술, 문제 해결 사례를 추출해 해당 경력에 연결한다.
- 근거가 없는 내용은 만들지 않는다. 모든 보강 항목에 출처 문서를 표시한다.

### 3.4 미리보기·편집

- 병합 결과를 이력서 형태로 렌더링하고, 기존 대비 변경점을 diff로 보여준다.
- 항목 단위로 수락·거절·직접 수정할 수 있다.

### 3.5 Notion 반영

- 확정된 이력서를 포트폴리오 페이지 아래 새 하위 페이지로 생성한다. (저장 위치는 가정안, 확인 필요)
- 기존 문서는 덮어쓰지 않는다. (비파괴 원칙)

## 5. Notion 데이터 구조

> 실제 워크스페이스를 API로 조회해 확인한 구조입니다. (2026-11-15)

### 5.1 포트폴리오 페이지

- 최상위 페이지 1개와 그 하위 페이지 4개(이력서·지원서 문서)로 구성된다. 데이터베이스는 없다.
- 모든 페이지의 속성은 `title`뿐이다. 날짜는 페이지 메타데이터(`created_time`, `last_edited_time`)를 사용한다.
- 본문은 페이지 content 블록이다. (제목, 문단, 불릿·번호 목록, 표, 인용, 이미지, 구분선)

### 5.2 환경 변수

```bash
NOTION_API_KEY=secret_xxx          # Notion Integration 토큰
NOTION_PORTFOLIO_PAGE_ID=xxxxxxxx  # 포트폴리오 페이지 ID
```

- AI API 키는 사용하지 않는다. (과금 회피 — 수동 연계 방식)

- 모든 키는 서버 전용이며 `NEXT_PUBLIC_` 접두사를 쓰지 않는다.
- 포트폴리오 페이지를 Notion Integration에 연결(Connections)해야 하위 페이지도 읽을 수 있다.
- `src/lib/env.ts`의 zod 스키마로 위 변수를 검증한다.

## 7. 아키텍처 및 데이터 흐름

```
Notion 포트폴리오 ─▶ 서버(하위 문서 조회·텍스트 변환) ─▶ 프롬프트 생성 ─▶ (사용자) ChatGPT 등에서 실행
                                                                              │ JSON 붙여 넣기
                                                                       Zod·출처 검증 ▼
                                   웹 미리보기(diff·편집) ◀─ 서버(정규화) ◀──────┘
                                              └─▶ 서버 ─▶ Notion 새 페이지
```

- Notion 호출은 모두 서버에서만 수행한다. AI 호출은 앱 밖(사용자)에서 이뤄진다.
- AI 결과는 JSON 스키마(경력, 프로젝트, 기술, 학력, 출처 포함)로 받고 Zod로 검증한다.
- 입력이 길어 챗 AI의 입력 한도를 넘을 수 있으므로, 프롬프트 길이를 점검하고 문서를 제외·나눠 실행하도록 안내한다.
- 후속으로 API 키를 설정하면 자동 호출 모드로 확장할 수 있도록 프롬프트 생성과 결과 검증을 분리해 둔다.
- Notion API 속도 제한(평균 3 req/s)에 대비해 요청을 직렬화·캐싱한다. 문서 본문은 Notion 마크다운 API로 문서당 1회 호출해 읽고(이미지·임베드 제거, 표는 | 행으로 변환), 쓸 수 없을 때만 중첩 블록을 하나씩 읽는 방식으로 되돌아간다.

### 7.1 권장 디렉토리

```
src/
├─ app/
│  ├─ resume/page.tsx
│  ├─ resume/merge/page.tsx
│  └─ api/resume/{sources,prompt,merge,save}/route.ts
├─ components/resume/     # 선택 목록, 미리보기, diff 컴포넌트
├─ lib/
│  ├─ notion.ts           # Notion 클라이언트·조회·저장
│  ├─ merge-prompt.ts     # 프롬프트 생성·AI 결과 JSON 추출
│  ├─ resume-normalize.ts # 정렬·중복 보정·출처 검증
│  └─ env.ts              # 환경변수 검증 (기존 파일 확장)
└─ types/resume.ts        # 이력서 스키마(Zod)
```

## 10. 비기능 요구사항

- **정확성**: 모든 AI 생성 항목에 출처를 표시하고, 근거 없는 내용은 만들지 않는다. 저장 전 사용자 검토는 필수다.
- **개인정보**: 이력서·지원서에는 개인정보가 포함되므로 외부 공개 라우트를 두지 않고 접근을 개인용으로 제한한다. HTTP Basic 인증(`BASIC_AUTH_USER`·`BASIC_AUTH_PASSWORD`)으로 `/resume`·`/api/resume`을 보호하며, 배포 환경에서 설정이 없으면 접속을 차단한다.
- **보안**: API 키는 서버 전용이며 저장소에 커밋하지 않는다. `.env.local`에만 저장한다.
- **안정성**: Notion 호출 실패 시 재시도와 명확한 오류 메시지를 제공한다. 붙여 넣은 AI 결과가 잘못되면 원인과 수정 방법을 안내한다.
- **비용**: AI API 과금 없이 동작한다. (수동 연계)
- **개인정보 주의**: 프롬프트에는 이력서 본문이 포함되므로 사용자가 외부 챗 AI에 붙여 넣기 전에 이를 인지하도록 안내 문구를 표시한다.
- **비파괴**: 기존 Notion 문서는 수정하지 않는다.
